# CareBridge · 케어브릿지

**서울대학교 산업공학과 「헬스케어 서비스 혁신」 수업 팀 프로젝트**

CareBridge는 비응급 전원·회송 결정 이후부터 수용기관의 첫 진료 회신과 의뢰기관 확인까지 시연하는 서비스 프로토타입입니다. 기관 탐색·수용 문의·정보 보완 과정의 반복 업무를 줄이고, 환자·보호자와 의료기관 사이의 연계를 지원하는 흐름을 설계했습니다.

Course project for Healthcare Service Innovation, Department of Industrial Engineering, Seoul National University.

**[프로토타입 체험하기](https://carebridge-prototype-gilt.vercel.app)**

## 실행

Node.js 22 이상. `npm run dev`로 실행한 뒤 http://127.0.0.1:4175 를 엽니다. 기본 시연·공개 기관 검색·경로 API는 별도 키 없이 동작합니다. AI 매칭·문의·회신 판단은 실제 LLM 인증이 필요하며, 실패하면 기본 시연 모드를 명시적으로 선택할 수 있습니다. 실제 AI 분석에는 OpenAI·Gemini 직접 API 키 또는 활성화된 Vercel AI Gateway 인증이 필요합니다. 배포본은 Google Gemini 직접 연결을 사용합니다.

`npm test`는 상태 전환·동의·역할·예외·HTTP API·배포 진입점을 검사합니다. `npm run build`는 정적 화면을 public/에 생성합니다.

## 시연 흐름

1. 의뢰기관에서 담당의 회송 결정을 확인하고 회송 정보를 점검합니다.
2. 환자·보호자가 선호 조건을 선택하고 기관 문의 동의를 체크한 뒤 ‘동의하고 기관 찾기’를 누릅니다.
3. Gemini가 검증된 기관 근거에서 추천 이유를 고르고 비식별 문의 초안을 작성합니다. 여러 기관 시연 API에 동시에 문의한 뒤, 회신을 Gemini가 인용·분석하고 수용 확인 후보를 공개합니다.
4. 환자가 기관을 비교·선택하고 해당 기관에 대한 정보 제공에 동의합니다.
5. 의뢰기관이 서류·이동 일정·환자 안내를 확인합니다.
6. 선택한 수용기관이 첫 진료 이행 여부를 회신합니다.
7. 의뢰기관이 회신을 확인해야 연계가 완료됩니다. 미이행은 재연계합니다.

정보 누락·수용 불가·동의 철회·추가 정보 요청·미이행 경로도 시연할 수 있습니다.

## 배포

GitHub에는 소스를 보관하고 Vercel에서 화면과 API를 함께 실행합니다. Vercel 설정은 framework Other, build command `npm run build`, output directory `public`, Node.js 22입니다. GitHub 자동 배포는 연결되어 있지 않으며 배포 소스를 직접 업로드합니다.

OpenAI 직접 연결은 Production 환경변수 `OPENAI_API_KEY`, Gemini 직접 연결은 `GEMINI_API_KEY`를 등록합니다. 키가 있는 제공자를 자동 선택하며, 둘 다 등록한 경우 `LLM_PROVIDER=openai` 또는 `LLM_PROVIDER=gemini`로 선택합니다. 기본 모델은 각각 `gpt-4.1-mini`, `gemini-3.1-flash-lite`이며 `LLM_MODEL`로 바꿀 수 있습니다. 직접 연결은 Vercel AI Gateway 크레딧을 사용하지 않습니다. 키 등록 후 재배포해야 합니다.

Gateway를 선택한 AI 분석은 요청별 `x-vercel-oidc-token` 또는 서버의 `AI_GATEWAY_API_KEY`를 사용합니다. 인증 정보를 브라우저에 노출하지 않습니다. AI Gateway 계정 승인·크레딧이 없으면 실제 분석을 완료한 것처럼 표시하지 않고 기본 항목 점검을 별도로 제공합니다. 2026-11-02 확인 당시 Gateway가 HTTP 403을 반환하여 결제수단 등록을 요구했습니다. 카드 등록은 사용자가 직접 수행해야 하며 임의로 결제·구매하지 않습니다. 계정 설정 후 서버 환경 변수 `AI_ANALYSIS_ENABLED=true`로 AI 버튼을 활성화할 수 있습니다. 현재 배포본은 Gemini 키를 Production의 sensitive 환경변수로 등록하여 Gateway 없이 직접 분석합니다. 정상 문서와 투여 간격 누락 문서의 실제 API 응답 HTTP 200을 확인했습니다.

- `web/`: 화면과 합성 데이터 모델
- `worker/api.mjs`: 공통 Request/Response API
- `worker/integrations.mjs`: 실제 AI 문서 분석·공개 의료기관 검색
- `worker/agents.mjs`: 실제 Gemini 업무 판단과 기관 시연 API
- `api/`: Vercel 서버 함수 진입점
- `public/`: 생성된 정적 파일 (Git 제외)
- `tests/`: 자동 테스트

## 시연 데이터와 한계

실제 환자 정보를 입력하지 마세요. 회송 시연의 환자·기관·처방·비용·수용 응답은 가상입니다. 기관별로 서로 다른 AI 생성 사진 5장을 사용하며 실제 병원 시설·품질을 나타내지 않습니다. 공개 기관 검색 화면의 이름·위치는 실제 OpenStreetMap 등록 정보이며 시연용 수용 문의에 사용되지 않습니다. 실제 병상·처치 역량·수용 여부는 확인되지 않습니다.

기관 문의는 실제 HTTP 시연 API로 처리하되 기관 응답 내용은 가상입니다. EMR/HIRA/실제 병상/예약/문자에 연결하지 않습니다. AI 분석은 준비된 합성 문서 두 종류만 허용하며 임의의 실제 문서나 프롬프트를 외부로 전송하지 않습니다. 실제 모델 응답을 원문과 대조하고, 미기재 항목을 추정한 결과는 거절합니다. 편집한 합성 문서는 규칙 기반 기본 점검으로 처리합니다.

서버 API는 문서의 입력 항목과 상태 전환 조건을 점검합니다. OSRM API는 고정 가상 좌표의 경로를 실제 조회하며 실시간 교통은 반영하지 않습니다. 새 회송 건은 Neon PostgreSQL에 저장합니다. 역할별 이용 링크로 같은 건을 연결하고 약 4초 간격으로 변경 내용을 확인합니다. 링크의 권한을 서버에서 검사하지만 의료기관 계정 로그인·본인 인증·임상 적합성 판단은 구현하지 않았습니다. 이전 버전의 브라우저 기록은 자동 업로드하지 않습니다.

## 공유 DB와 새 회송 시작 (2026-11-03)

상단 **처음부터 시작 → 새 회송으로 시작**을 누르면 동의·선택·응답이 없는 독립 회송 건을 만듭니다. 기존 DB 회송을 지우거나 초기화하지 않습니다. 기존 건은 이전 이용 링크 또는 첫 화면의 기록 목록에서 이어갈 수 있습니다. 로고는 기록을 유지하고 첫 화면으로 이동합니다. 이전 버전의 로컬 기록도 보관하고 첫 화면에서 다시 열 수 있습니다.

**이용 링크** 버튼에서 의뢰기관·환자·각 수용기관 링크를 복사해 다른 기기에서 엽니다. 처음 만든 브라우저만 전체 역할 링크를 갖고, 참여자는 전달받은 역할 링크만 갖습니다. 링크는 해당 건의 접근 권한이므로 해당 참여자에게만 전달합니다. 로그인 기반 신원 인증이나 링크 만료·회수 기능은 아직 없습니다. 실제 환자 자료를 저장하는 용도가 아닙니다.

- 실제 배포 저장소: Vercel Marketplace의 Neon PostgreSQL. 서버 환경변수 `DATABASE_URL`을 사용하고 연결 정보는 프런트엔드에 포함하지 않습니다.
- SQL: `db/schema.sql` / 실행 원본: `worker/schema.mjs`. 초기 접속 시 `CREATE TABLE IF NOT EXISTS`로 구성하며 기존 테이블을 삭제하지 않습니다.
- 테이블: `cb_cases`(공용 상태·버전), `cb_access`(역할별 토큰 해시), `cb_inquiries`(기관별 문의·회신), `cb_consents`(동의 변경), `cb_events`(처리 이력), `cb_requests`(중복 요청 방지).
- 상태 변경은 DB의 기존 상태를 기준으로 검증하고 버전이 다르면 최신 기록을 전달합니다. 상태·문의·동의·이력 저장은 단일 SQL 문으로 원자적으로 처리합니다.
- 수용기관에는 선택·정보 제공 동의 전 식별명과 상세 처방을 반환하지 않습니다. 다른 기관의 회신·환자 선택·의뢰기관 확인 작업도 권한 검사합니다.
- 공유 자동 진행은 서버가 저장된 상태를 읽어 실제 LLM과 합성 기관 응답 모듈을 실행합니다. 브라우저가 보낸 임의의 자동 완료 결과는 저장하지 않습니다.
- 로컬 SQL 검증: `CAREBRIDGE_LOCAL_DB=./review/local-postgres npm run dev` (개발 의존성 PGlite 사용). 운영 DB는 Neon PostgreSQL이며 로컬 파일 DB를 배포 저장소로 사용하지 않습니다.
- `npm test`는 PostgreSQL SQL 호환 엔진에서 저장 지속성·중복 요청·충돌·역할 권한·전체 회송 흐름도 검증합니다.

## 사진·경로 출처

시설 사진은 OpenAI image_gen으로 생성했습니다. 새봄: 대기 공간, 솔빛: 재활 운동실, 다온: 병원 외관, 봄길: 회복 병실, 해온: 처치 준비 공간. 생성 지시에는 인물·문자·로고·실제 기관 표시를 제외하고 비미래적인 한국 병원 환경, 자연광을 요청했습니다. 생성된 원본은 별도로 보존하며 배포용 JPEG만 web/assets에 포함합니다.

OSRM / © OpenStreetMap contributors. API 문서: https://project-osrm.org/docs/v5.24.0/api/ . 공개 데모 서버는 가용성을 보장하지 않으며 장애 시 조회 실패로 표시합니다.

공개 기관 검색: OpenStreetMap / Nominatim. [이용 정책](https://operations.osmfoundation.org/policies/nominatim/). 세 지역의 제한된 사용자 요청만 처리하고 자동완성·주기적 수집은 하지 않습니다. 애플리케이션 식별 헤더, 함수 내 1.1초 호출 간격, 6시간 메모리·배포 CDN 캐시를 적용합니다. 소규모 수업 시연용으로 사용하며 대규모 공개 운영 전에 전용 제공자와 전역 호출 제한이 필요합니다. 서버 환경 변수 `HOSPITAL_DIRECTORY_API_URL`로 제공자를 교체할 수 있습니다.

AI API: [Google Gemini OpenAI 호환 API](https://ai.google.dev/gemini-api/docs/openai), 현재 배포 모델 `gemini-3.5-flash-lite`. OpenAI 직접 연결과 [Vercel AI Gateway OIDC](https://vercel.com/docs/ai-gateway/authentication-and-byok/oidc)도 선택 가능합니다. 준비된 합성 문서의 검증된 응답은 24시간 배포 CDN 캐시를 사용합니다. AI 분석은 처방의 적절성이나 임상 안전성을 검증하지 않습니다.

일시적인 제공자 404/429/5xx 또는 연결 오류는 제한된 횟수로 재시도하고, Gemini 모델 간 대체 요청을 수행합니다. 최종 결과에는 실제 사용한 모델을 기록하며, 모든 시도가 실패하면 분석 완료로 표시하지 않습니다.

## UX 개선 v4

각 단계 상단에 현재 담당과 다음 행동을 안내하고, 역할 전환과 실제 작업을 연결했습니다. 가능·불가·확인 전은 초록·빨강·주황과 기호·문구를 함께 사용합니다. 처치 역량과 환자별 수용 응답은 별도 상태로 표시합니다. 기관 비교 선택 내역과 비교표 내 기관 선택을 지원하며, 업무 화면의 사진·카드는 압축했습니다.

51개 자동 테스트와 브라우저의 동의·비교·예외·모바일 흐름을 검증했습니다. 실제 사용자 대상 사용성 평가 결과는 아닙니다. 근거와 검증 범위는 [UX-REVIEW-v4.md](UX-REVIEW-v4.md)를 참조하세요.

## Proposal 기능 구현 v5

제안서의 Solution·Value Proposition·Technology·AI Component(19–22p)를 확인해 문서 추출 외의 매칭·문의·회신·재탐색을 구현했습니다.

- 네 가지 가상 생활 조건을 필수 필터와 다기준 점수에 반영합니다. 거리·비용 외에 가상 기관 평가, 응답률과 수용 정보 불일치 이력을 점수에 포함합니다.
- Gemini가 추천 근거를 선택하고 비식별 문의 초안을 작성합니다. 추천 후보·순서·근거는 코드가 검증하며, 모델이 처치 조건이나 점수를 바꾸지 못합니다.
- `/api/facility`에 여러 기관 문의를 동시에 보내며 요청 payload 자체에 식별명·약제·상세 처방을 포함하지 않습니다. 응답에는 가상 기관의 회신 원문과 요청 ID가 남습니다.
- Gemini가 기관 회신을 정확한 인용과 함께 분류하고 다음 작업을 제안합니다. 허용된 단계·기관 응답과 다르면 실행하지 않습니다.
- 환자의 후보 거절 사유를 재탐색 조건에 반영하며 재동의를 받습니다. 기관 등록 정보 변경과 무응답 예외도 처리합니다.
- `/api/agent`는 준비된 합성 상태만 받고, 모델에 자유서술 보완 메모나 상세 처방을 보내지 않습니다. 동일 조건 캐시와 제한된 재시도·요청 제한을 적용합니다.

실제 병원 접속·EMR/HIRA·문자·동기화·의료용 인증은 연결하지 않았습니다. 기관 평가·응답 이력·병상·환자 조건은 가상 예시입니다. 점수는 임상적 적합성 평가나 실제 수용 확률이 아닙니다. 제안서 대비 구현 및 남은 연결 범위는 [PROPOSAL-IMPLEMENTATION.md](PROPOSAL-IMPLEMENTATION.md)에 기록했습니다.
